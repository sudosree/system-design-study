How to improve the booking experience

1. Pessimistic Locking (Two phase locking)
- locks the row on database (done through SELECT FOR UPDATE statement)
- other transaction needs to wait
- how lock will be released ?
- when transaction is committed then lock is released
- if user is taking long time or it abandons the purchase then the system has to rely on their subsequent actions 
or session timeouts to release the lock. 
Pros
- prevents simultaneous update
- useful when data contention is heavy
Cons
- not scalable because if the transaction is locked for a long time it increases the risk of lock contention and deadlock,
impact the database performance

2. Reserved Status and Expiration Time with Cron Job
- ticket status - available/reserved/booked
- when user tries to book the ticket, status is changed to reserved, set the expiration time as well
- If the expiration time is reached then lock is automatically released
-  If the booking is successful then the status changed to booked and the lock is released
- If user unable to book the ticket and the expiration time is reached then the status changed back to available and the lock is released
- How expiration time is handled ? (using cron job) runs periodically and check if the time elapsed exceeds the expiration time
- Cons
- delay in unlocking

3. Reserved Status and Expiration Time 
- ticket status - available/reserved/booked
- when request comes, system check the availability of ticket by checking the status as available or reserved with expired timestamp
- If the expiration time is reached or the status is available then user can book the ticket, set the status to reserved (+10 mins exp)
- If the booking is successful then set the status to booked and the lock is released

4. Distributed Lock with Redis
- store a lock using key value pair in redis
- <ticket-id>:<user-id> (set expiration time for the lock)
- ticket status - available/booked
- user tries to book the tickets, it acquire the lock on redis
- if the purchase is successful then it updates the status to booked and released the lock
- else if not or the expiration time is reached then the lock is automatically released and the status changed to available


Flow
- request goes to Booking Service
- Booking service acquires the lock from Redis
- BS creates a booking record in the Booking table and set the status to in-progress
- BS send the payment info along with booking id to Stripe
- once the payment is succ then it updates the ticket status to booked and booking status to confirmed
