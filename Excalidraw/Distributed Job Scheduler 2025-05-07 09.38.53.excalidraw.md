# Excalidraw Data
## Text Elements
FR
- user should be able to schedule jobs to be executed immediately, at a future date, on a recurring schedule
- user should be able to check the status of jobs

NFR
- Availability > Consistency
- Jobs should be executed within 2 s of their scheduled time
- Scalable - 10K jobs per sec ^LncRhK1Z

Job - an instance of a task needs to be executed
- consists of a task
- schedule for when the task needs to be executed
- the parameters needed to execute the task


Core Entities
- User (schedules the job)
- Task
- Job
- Schedule (schedule for when the job needs to be executed, can be a CRON exp. or spec date time) ^a6W6tq21

API Design

1) Schedule a job
POST /jobs

{
    "taskId": ....
    "schedule": ....
    "parameters": {
        ...
    }
}

 ^dYfnb3qb

2) Monitor the status of jobs
GET /jobs?status={status}&startTime={startTime}&endTime={endTime} ^vvfrt6lD

Data Flow
- user schedules a job by providing the following info - task to be executed, schedule and parameters
- job is created and stored in the system
- job is executed at the schedule time by the worker, if the execution fails it is retried using exponential backoff
- job's status is updated in the system



HLD


 ^IxtSMoog
