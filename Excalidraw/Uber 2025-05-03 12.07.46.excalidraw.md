# Excalidraw Data
## Text Elements
Functional Requirements
- users should be able to input the src and dest and get an estimated fare
- users should be able to request a ride based on the estimated fare to be matched with the nearby available driver
- drivers should be able to accept/deny the request and navigate to pickup/dropoff

NFR
- low latency for ride matching < 1min else failure (should happen asynchronously)
- system should be highly consistent in ride matching, ride to driver matching is 1:1, a ride shouldn't be assigned to multiple drivers
- apart from the ride matching everything is high availability
- system should be able to handle high throughput, surges during peak hrs or some special event - 100k requests



Core Entities
- Ride
- Rider
- Driver
- Location


API Design
- POST /ride/estimate-fare -> Ride
{
    src, dest
}

- PATCH /ride/request-ride -> Success/Error (ride matching will happen in the backend asynchronously)
{
    rideId
}

- Drivers update their location by calling the below API
- POST /location/update - Success/Error
{
    lat, long
}

- PATCH /ride/match -> Ride
{ 
    accept/deny
}
