Deep Dive

How short urls are generated ????
- shortUrl has 62 possible characters
- 62^n >= 300 billion -> n = 7 -> 3.5 trillion urls can be generated with len = 7

1st Approach (Hash Function plus Timestamp)
- use a hash function like MD5, SHA-1 to generate the hash of a long url
- MD5 has 128 bit hash value which is very long so take the first 7 bytes from the hash value
- can lead to collision
- resolve it by adding timestamp and again regenerate the hash


2nd Approach (Hash Function plus base 62 conversion plus Timestamp)
- take the first 7 bytes from the hash value of 128 bit long
- convert it into decimal
- convert the decimal into base 62
- can lead to collision
- resolve it by adding timestamp and again regenerate the hash


3rd Approach (Distributed Unique ID Generator and base 62 conversion)
- generate a unique id for every new long url and convert the id into base 62
- length of the short url will vary depending on the unique id generated ^tzUdByEc

URL shortening request flow
- request comes to the load balancer
- lb forwards the request to the generation service
- url generation service checks if the long url is present in the db or not
- if it is present then return it
- else generate the short url, save it in the db and return it ^p5wUTFNc

URL redirection request flow
- request comes to the load balancer
- lb forwards the request to the redirection service
- redirection service checks if the short url is present in the db or not, if it is present then return the long url
- else return error ^DQtGMU4K

Scalability
- scale API server - by adding or removing multiple instances of the services
- database sharding using consistent hashing
- shard key -> short url
- generate the hash of the short url and store it in a shard
- retrieve the corresponding long url from the shard by generating the hash of a short url
- use cache to store frequently access short urls
(Redis, memcached)
